A GhostMesh Reader deconstruction of AI LABS, “EGM: Google’s New Way To Use Claude Code Is Insane.”

GhostMesh judgment: adapt the separation between author and reviewer before adopting the whole review apparatus. EGM makes a useful demand: a specification should survive outside the conversation that produced it. That can reveal assumptions the author has stopped noticing. The harder question is whether the next reviewer can find something consequential that the first context could not, at a cost the decision warrants.

That is a higher standard than producing more criticism. A busy review can leave the same underlying error intact.

The conversation has become part of the specification

The AI LABS walkthrough describes an Elephant that develops a plan with the user and Goldfish reviewers that examine the plan without that earlier conversation. Around 02:15, the narration makes that separation central to its account of the method. The pinned EGM README describes the reviewers as receiving the document and referenced source material, while people retain responsibility for trade-offs and approval.

The useful diagnosis is familiar to anyone who has worked through a long design conversation. We answer a question in chat, revise a proposal, and gradually build a shared understanding. Then we ask the same context whether the resulting document is clear. It can supply the missing explanation from memory. The document appears more complete than it is.

A new reader cannot do that so easily. If the design depends on an exception discussed earlier, the reader must find the exception in the supplied evidence, ask about it, or make a guess. That interruption is valuable. It turns conversational understanding into something another person or agent can inspect.

But the specification cannot preserve every conversation. The objective is to preserve the decisions and constraints needed to build, operate and change the feature. A document that exhaustively records discussion can still conceal the one unresolved authority question that matters.

Freshness is a property of context; independence needs more evidence

EGM gives reviewers different lenses and separates their context from the author’s. Its review instructions include comprehension, critique, broader reconsideration and implementation readiness. The comprehension step is particularly useful: ask another reader to explain the plan before celebrating its criticism. A confident paraphrase can expose a consequential misunderstanding.

Still, fresh reviewers can share a way of being wrong. They may use the same model family, accept the same incomplete source material, or apply standards that emphasize structural completeness while overlooking a business constraint. Different role names do not establish different error distributions.

Consider a hypothetical deletion feature. Every reviewer receives a technically coherent design and the same database schema. None receives the contractual requirement to retain a record for a defined period. Several reviewers could independently improve the deletion mechanism while missing the reason it should not operate that way at all. Their agreement would be real; the evidence supplied to them would remain insufficient.

The right question is therefore what changed between reviews. Was the second reader given a different source of evidence, a different responsibility, or an explicit attempt to disprove a key assumption? Context isolation can remove the author’s conversational momentum. It does not automatically introduce the missing constraint.

The contract can be wrong before the code drifts

Around 07:08, the walkthrough turns toward mapping an existing application. The bootstrap instructions at the inspected revision describe documentation of interfaces, invariants and side effects.

Later, around 14:18, the presenter reports a drift finding involving deletion of previously sold products. That is a narrated outcome, not a bug reproduced in this review.

The broader idea deserves attention. A checked-in statement of intended behavior creates something against which later code can be compared. Otherwise, a change can quietly become the new explanation of what the system was supposed to do.

Yet the authority of that statement matters. A rule inferred from current code describes an implementation; it may not establish the policy the implementation should enforce. Conversely, a rule in a design may be obsolete, incomplete or deliberately superseded. Finding a mismatch begins a decision about which side should change.

The drift-report instructions direct the agent to inspect documents and source and report discrepancies. That is a useful comparison mechanism. Its findings still need an accountable reader who can distinguish a defect from an intentional exception or a stale document. Otherwise, a review system can become an efficient producer of reasons to restore yesterday’s mistake.

For GhostMesh, this makes provenance part of a design contract. Which invariant came from an owner decision, which came from a test, and which was inferred from code? A reviewer should be able to challenge each with the appropriate evidence. Merely storing all three in the same README does not give them equal authority.

The strongest objection is that the extra review may be the point

A feature involving irreversible effects or difficult migration can justify substantial preparation. The cost of reviewing an unnecessary concern may be small compared with discovering one serious omission after deployment. Structured stages also make it harder to call a quick skim an independent review.

That is the strongest case for EGM’s fuller workflow, and it should not be dismissed as ceremony. A review can earn its cost by preventing a single expensive mistake. Nor does a false positive make the whole method useless.

The limit is that possible benefit is easy to invoke after every additional round. Without a stopping rule, the process can reward the volume of criticism rather than the quality of decisions. Someone must read, reject, reconcile and close the findings. That labor belongs in the cost of the review, even when launching another agent feels cheap.

EGM’s own README makes room for ordinary small-fix workflows. Its testing record also distinguishes structural checks, native workflow fixtures and unresolved cloud-verification gaps. Those records help assess whether the machinery ran as intended. They do not establish a reduction in production defects or the incremental value of each reviewer. The project also states that it is not an officially supported Google product.

Compare against the review we already have

GhostMesh already depends on separate source custody, independent review, an accountable publisher and explicit authority for consequential releases. The useful comparison is against those existing responsibilities. A new framework should improve a known weakness in that process rather than receive credit for introducing review to an imaginary system that had none.

The next useful evaluation would be a bounded comparison on a specification with a genuine unresolved decision. Keep the existing review as the baseline. Separately record what fresh-context review identifies, which findings survive adjudication, which were already known, which are wrong, and how much effort resolving them takes. Agree on severity before seeing which workflow produced a finding. Keep human time, model use and correction work in the accounting.

That evaluation is proposed, not performed here. It would support adaptation if the additional review exposed consequential omissions that the existing process missed and did so at a defensible total cost. It would argue for a narrower use if it mostly repeated findings or created disputes that better source context could have prevented. A serious disagreement might require a different primary source rather than another reviewer.

EGM’s most portable contribution is the demand that a plan survive another reader. GhostMesh should retain that demand and judge the machinery by the decisions it improves. A review is ready to stop when its material findings have owners and dispositions, its unresolved assumptions remain visible, and the authorized next action is clear. More agents cannot supply that accountability by agreeing with one another.
