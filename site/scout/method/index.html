How Scout works

Scout is a public-source editorial review, not a product certification or an installation pipeline. Its job is to show why a candidate deserves attention, what was inspected, what remains unknown and what experiment could change the call. GhostMesh fit and everyday usefulness are separate questions. Popularity does not answer either one.

How a candidate enters view

The current scanner watches a curated GitHub repository list and makes a small weekly search of public repositories in AI agents and code analysis. The source configuration names two GitHub topic queries and explicit editorial priorities. The scanner requests five recently updated results per query, fetches at most 15 repository metadata records, shortlists five and reserves up to three deeper assessment slots. These limits bound a scan; they are not a ranking of quality. The scanner configuration and history are retained privately, so this public page describes their relevant method without pretending those internal files are public evidence links.

The first edition's Cloudflare, Graphify and OpenShell reviews came from those explicit priorities. The retained history records a first observation on October 21, 2026, but not when someone originally discovered each project. Search query attribution and rank were not retained. The current editorial reasons for examining them are stated on their review pages; those reasons do not reconstruct an unrecorded historical choice.

What a review means

Discovery records a candidate. An editor decides what question is worth asking and checks bounded public material. A repository README and policy review is documentation review; inspecting some implementation source is narrower than a full code audit. Neither establishes runtime behavior, independent performance or security outcomes. Each review names the pinned version, actual materials, untested claims, audience, potential GhostMesh use, everyday value, tradeoffs and counterevidence. Any execution or independent measurement would have to be named separately and supported by a new record.

The current scanner collects public metadata and reuses an analyst assessment only when the repository commit still matches. It does not automatically write or approve the qualitative Reader you see here. Papers, articles and other tools may be reviewed through a qualified future source path; the current weekly scanner is GitHub repository only. Private scanner artifacts are not copied into this site.

How judgments change

A review has a stable URL. A dated edition explains why several reviews belong together; the library keeps every approved review browsable even after it leaves the homepage. A re-review records the new source version, date, what changed and the earlier judgment. Popularity may appear only as a sourced, dated observation, never as a quality rating; no historical star or fork snapshot was captured for this edition.

Only a first public review or a material approved revision receives a stable RSS release event. Rebuilds, layout edits and popularity changes do not produce feed entries. A preview is not a publication date. Editorial acceptance and production release remain separate decisions.
