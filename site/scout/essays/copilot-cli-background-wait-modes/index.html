Copilot CLI 1.0.104 documents different background-task waits by mode

GitHub’s release notes distinguish interactive and SDK Autopilot waiting from the timeout retained by prompt-mode Autopilot.

Source-reported; not independently tested · Published October 28, 2026 · Reviewed October 28, 2026

Source-reported; not independently tested
Observation date: October 28, 2026. Source release: October 27, 2026.

GitHub's Copilot CLI 1.0.104 release notes describe a change to waiting for attached background tasks. The notes say interactive and SDK Autopilot sessions continue waiting rather than stopping at COPILOT_TASK_WAIT_TIMEOUT_SECONDS. They explicitly retain that timeout for -p --autopilot.

The command reference describes that variable as the wait limit for pending background agents or shell commands in -p, including -p --autopilot. It lists a default of 600 seconds and says zero exits without waiting.

The release entry is also present in the repository changelog at commit 8f18becc073481aeab76c83bc38d6db8c3d6c85a. At inspection, 1.0.105 was the latest stable release; its note concerns model selection from long-context sessions, not another background-wait change.

This report records the published mode distinction. Scout did not install Copilot, execute a session, inspect runtime implementation, or verify behavior in any account. A documented wait rule is not a verified task-completion result.
