# Scout and site subscriptions

The existing static generator publishes one public Scout page and one site-wide RSS feed. It does not read the Skills scanner output or private scout artifacts. Skills #358 retains discovery custody, source paths and scheduler. A separately prepared assessment based on public sources may be handed to the existing Readers publisher with pinned links and an honest inspection record. The publisher prepares public-safe candidate cards in `content/scout-public.json` for independent editorial review and Tony's preview/content approval. Production admission requires Tony's separate exact release decision. This narrow authorship option grants no access to Skills private artifacts or authority over its producer.

Each Scout card needs a stable ID, original HTTPS source, review date, actual inspection method, confidence, a short product identity and review scope, a bounded summary, explicit unknowns, and four ratings with public source-linked rationale: GhostMesh fit, everyday usefulness, evidence strength and adoption effort. The long argument appears once in the public report; scorecards show the identity, scope, call and expandable rating rationale. A metadata review does not claim source inspection; source inspection does not claim execution or independent measurement. Empty cards mean no candidate has yet been cleared for publication.

`content/public-release-events.json` is the one immutable public event list for the RSS feed. Add an event only for a first public Reader release, a substantive approved Reader revision, or a newly published/materially revised Scout review. Each event uses a stable subject-bound ID, canonical URL and verified public calendar date; `releasedAt` is optional and must be a genuine timezone-aware release timestamp. Date-only events have no RSS `pubDate`; the generator never invents an hour from a candidate's `published` or `updated` field. Routine builds, checks, layout changes and unpublished drafts add no event. Existing Readers are not backfilled with guessed release times. A new event is part of the normal reviewed publication source change; its RSS projection updates in the same deterministic build. RSS clients receive one item per stable event ID rather than a duplicate from each rebuild.

The `/scout/` page starts empty and receives only a real reviewed assessment from either the Skills custodian or the public-source editorial path above. The existing Readers editorial owner clears specific public fields before preview; Tony accepts the content and exact release separately. This does not approve adoption, private artifact publication, new inference spending, or #45 artwork.
