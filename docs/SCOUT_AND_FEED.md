# Scout and site subscriptions

The existing static generator publishes a bounded `/scout/` home, a `/scout/archive/` review library, `/scout/method/`, dated editions and permanent `/scout/reviews/<id>/` pages. It also publishes one site-wide RSS feed. It does not read the Skills scanner output or private scout artifacts. Skills #358 retains discovery custody, source paths and scheduler. A separately prepared assessment based on public sources may be handed to the existing Readers publisher with pinned links and an honest inspection record. The publisher prepares public-safe records in `content/scout-public.json`, full reviewed narratives in `content/scout/reviews/`, and edition metadata and synthesis in `content/scout-editions.json` and `content/scout/editions/`. Independent editorial review and Tony's preview/content approval precede publication. Production admission requires Tony's separate exact release decision. This narrow authorship option grants no access to Skills private artifacts or authority over its producer.

Each Scout record needs a stable ID, original HTTPS source, review date, actual inspection method, confidence, product identity, audience, review scope, topic, source type, recommendation, explicit unknowns, and four ratings with public source-linked rationale: GhostMesh fit, everyday usefulness, evidence strength and adoption effort. The full argument appears once on its permanent review page; the home, edition and library link to it. The record separately identifies the retained discovery route, current editorial reason for selection, actual inspection and dated prior reviews. The first edition's three reviews were explicit priorities in the pinned Scout configuration; original discovery query and rank were not retained. A metadata review does not claim source inspection; source inspection does not claim execution or independent measurement. No historical popularity count is inferred.

`content/public-release-events.json` is the one immutable public event list for the RSS feed. Add an event only for a first public Reader release, a substantive approved Reader revision, or a newly published/materially revised Scout review. Each event uses a stable subject-bound ID, canonical URL and verified public calendar date; `releasedAt` is optional and must be a genuine timezone-aware release timestamp. Date-only events have no RSS `pubDate`; the generator never invents an hour from a candidate's `published` or `updated` field. Routine builds, checks, layout changes and unpublished drafts add no event. Existing Readers are not backfilled with guessed release times. A new event is part of the normal reviewed publication source change; its RSS projection updates in the same deterministic build. RSS clients receive one item per stable event ID rather than a duplicate from each rebuild.

The first-edition source is a preview until accepted and released. Its date is a review date, not a public release date. A future revision must retain its prior judgment in the dated history and add an RSS event only when a material revision actually publishes. The existing Readers editorial owner clears specific public fields before preview; Tony accepts the content and exact release separately. This does not approve adoption, private artifact publication, new inference spending, or #45 artwork.
