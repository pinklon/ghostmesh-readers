# Reader release runbook

This is the one publication queue and release path for `pinklon/ghostmesh-readers`. One accepted publisher owns a candidate from source handoff through the final production receipt. Source custodians and independent reviewers can supply evidence or read-only findings; they do not start competing uploads. The public repository contains original analysis and sanitized receipts, never copied media, captions, full transcripts, private source packs, signed URLs, or credentials.

## Reader release contract v2 (owner-approved November 9, 2026)

For Reader #48 onward, one explicit owner decision to **publish the reviewed candidate** authorizes the normal transition from draft to ready, protected merge, and the existing GitHub-to-Netlify Production deployment, provided the exact candidate and required checks remain unchanged and passing. No subsequent conversational approval is required for those routine steps. An editorial acceptance that does **not** say publish remains editorial-only; never infer deployment authority from a review comment or a thumbs-up on ambiguous material.

**One bounded pass:** complete the manuscript, claim/source/privacy review, and both relationship assessments; generate the existing site projections; run existing CI; inspect the deployed preview at desktop and narrow mobile width; then release the identical head. Reuse passing, hash-bound checks and prior editorial findings. Re-run only when their relevant inputs change or a genuine failure occurs. No new orchestrator, queue, publisher, broad site rewrite, or duplicate independent review.

**First-candidate preflight:** before opening the PR, compare the full locked manuscript (including all relationship rationales and final limitations) to the rendered page, check both relationship layers, confirm public-safe attribution and private-source exclusions, and validate source-map claim/timestamp consistency and existing review/receipt hashes. Fix candidate defects before requesting owner review. The existing focused tests, local site check and one normal CI gate perform these checks; do not create a second acceptance workflow or rerun unrelated checks for unchanged inputs.

**Independent review before publish request:** as soon as the candidate's authored article, source map and private-aid digest are stable, request the existing independent editorial/source/privacy review on those exact inputs. Retain its actual findings in `content/editorial-reviews/<slug>.json` and the associated depth assessment in `content/editorial-depth/<slug>.json`; report `PENDING` or `HOLD` honestly until both are valid. The publisher may open a draft PR and preview while review is pending, but must not present it as a release-qualified candidate or ask Tony for the final publish decision. The owner-facing publish packet must include the accepted review, bound hashes, CI result, preview UAT, both relationship assessments and the exact proposed head together. After a substantive correction, re-review only changed editorial/source/privacy inputs and refresh their bindings before requesting publication. This sequencing uses the existing reviewer and release gate, with no extra approval or review layer.

**Stop and return to Tony only for:** a material editorial or source change after approval; failed required checks; missing/invalid private-source boundary; privacy or security concern; changed candidate head; or an explicit owner hold. A minor non-misleading administrative receipt label does not roll back a verified article, but must be corrected in the next ordinary maintenance change. Never bypass branch protections.

**Completion:** GitHub merge is only merged, not deployed. Confirm the public URL, full article, source disclosures, local Reader relationships, separately labeled SharePlane links, and production receipt. Record commit, live URL, time and any known limitations in the existing queue. Publication state must be described from actual merge/deployment evidence, never from draft-stage boilerplate.

**Performance target:** one publication approval, zero routine follow-up approvals, and minutes of release overhead after the manuscript is ready. This is an operating target; record actual interventions and elapsed time on Reader #48 before claiming it achieved.

## Proportionate editorial depth

The reviewer first states why the source calls for a brief or extended treatment. A long source, many material claims or a consequential architecture recommendation requires extended mapping.
