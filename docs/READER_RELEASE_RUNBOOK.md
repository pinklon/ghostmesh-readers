# Reader release runbook

This is the one publication queue and release path for `pinklon/ghostmesh-readers`. One accepted publisher owns a candidate from source handoff through the final production receipt. Source custodians and independent reviewers can supply evidence or read-only findings; they do not start competing uploads. The public repository contains original analysis and sanitized receipts, never copied media, captions, full transcripts, private source packs, signed URLs, or credentials.

## Reader release contract v2 (owner-approved November 9, 2026)

For Reader #48 onward, one explicit owner decision to **publish the reviewed candidate** authorizes the normal transition from draft to ready, protected merge, and the existing GitHub-to-Netlify Production deployment, provided the exact candidate and required checks remain unchanged and passing. No subsequent conversational approval is required for those routine steps. An editorial acceptance that does **not** say publish remains editorial-only; never infer deployment authority from a review comment or a thumbs-up on ambiguous material.

**One bounded pass:** complete the manuscript, claim/source/privacy review, and both relationship assessments; generate the existing site projections; run existing CI; inspect the deployed preview at desktop and narrow mobile width; then release the identical head. Reuse passing, hash-bound checks and prior editorial findings. Re-run only when their relevant inputs change or a genuine failure occurs. No new orchestrator, queue, publisher, broad site rewrite, or duplicate independent review.

**Stop and return to Tony only for:** a material editorial or source change after approval; failed required checks; missing/invalid private-source boundary; privacy or security concern; changed candidate head; or an explicit owner hold. A minor non-misleading administrative receipt label does not roll back a verified article, but must be corrected in the next ordinary maintenance change. Never bypass branch protections.

**Completion:** GitHub merge is only merged, not deployed. Confirm the public URL, full article, source disclosures, local Reader relationships, separately labeled SharePlane links, and production receipt. Record commit, live URL, time and any known limitations in the existing queue. Publication state must be described from actual merge/deployment evidence, never from draft-stage boilerplate.

**Performance target:** one publication approval, zero routine follow-up approvals, and minutes of release overhead after the manuscript is ready. This is an operating target; record actual interventions and elapsed time on Reader #48 before claiming it achieved.

## Source acquisition: discover the commissioned surface first

A browser reporting missing captions is **not** a source-acquisition failure. Before requesting a manual transcript, discover the existing remote tools and call `list_devices` when Remote Desktop Commander is available. Resolve the commissioned source custodian and documented fallback from private custody; do not publish device names, inventory, IDs or paths. On the admitted surface, record the actual CLI path/version and `reasonpack doctor` result. Use `inspect`, `build` and `verify` only within the accepted source job and private output boundary; discovery alone does not authorize acquisition. A missing cloud executable does not establish that the commissioned capability is absent. Confirm any configured local Whisper fallback rather than assuming it exists; report an unconfigured or unverified fallback explicitly. Honor source rate limits and actual denials without importing cookies or rerouting the denied operation. Retain private command/exit/hash receipts; public evidence uses role names and capability limits. See [ReasonPack discovery issue #46](https://github.com/pinklon/reasonpack/issues/46) for cross-host convergence, which this runbook change does not itself complete. Reuse the source custodian and publisher; do not add a dispatcher, capture job or publication lane.

The former Scout `routine-source-report-v1` standing publication exception is suspended for new works as of October 29, 2026, because source fidelity and mechanical checks admitted public pages without substantive GhostMesh analysis. The hosted routine-release guard now rejects new reports in that class. Preserve existing published history, retain source-only findings as private research input, and take substantive public candidates through the ordinary editorial, preview and exact-head release path in [SCOUT_RESEARCH_CONTRIBUTING.md](SCOUT_RESEARCH_CONTRIBUTING.md). This does not change the direct owner editorial marker or exact-head gate for Readers.

## Video Reader template and length

Start each video Reader from the [published Pando Reader](https://youtube.shareplane.malott.ai/when-code-gets-cheap-where-does-the-work-wait/) and its [authored HTML](../content/readers/when-code-gets-cheap-where-does-the-work-wait.html). Copy the authored source to the new slug. Keep the layout, shared header and footer, and mobile-readable evidence rows. Replace the Pando title, source, cues, claims, related links, and provenance with the new work’s material. Choose the length at intake and reuse the same page structure.

| Reader length | Starting ReasonPack profile | Editorial scope |
| --- | --- | --- |
| Brief | `short` | One central finding, the strongest evidence, its main limitation, and the practical takeaway. |
| Short | `standard` | The material claims and counterevidence, what they mean in practice, and one clear recommendation. |
| Long | `deep` | A fuller account of the tools and workflow, meaningful alternatives, counterarguments, and a bounded trial when warranted. |

Use ReasonPack's existing `exhaustive` profile for reference-grade work when requested. These are starting profiles. The source and stakes determine the depth of review. The existing release receipt still requires extended review for a source of at least 30 minutes, eight or more claims, or a proposed architecture change.

Keep this reading order for every length.

1. Three-part brief, headline, speaker identity and role, and a specific recommendation.
2. Opt-in inline player, original-source fallback, and meaningful timestamp labels.
3. The article and its conclusion.
4. Claim register, counterevidence, external references, and evidence independence.
5. Populated related reading and **Continue the thinking**.
6. Source scope and provenance at the end. Keep sanitized receipt links with the supporting material.

Keep the generation slots used by the Pando source. Use `GM_RELATED` for approved catalog relationships. For proposed reading links only, keep the populated authored section with the `related-thinking` anchor and a dated zero-edge rationale in the catalog. Chapter labels should name a specific tool, demonstration, decision, or failure mode. The generator supplies the standard share control when the source has none. Add the new Reader’s archive recommendation to the existing `CALLS` table in `scripts/catalog_design.py` when adding its catalog record.

For a clean-room replay, give a new operator only the source URL, canonical ReasonPack/Reader instructions and the selected editorial depth. It must emit a private verified source pack, immutable depth selection and analysis receipt, source-specific chapters and evidence map, Reader preview with full shared chrome, and an explicit stop before public merge. Record job/pack/hash/PR/CI/preview and human review evidence in the existing queue; do not create a second tracker. ReasonPack draft PRs [#27](https://github.com/pinklon/reasonpack/pull/27) and [#31](https://github.com/pinklon/reasonpack/pull/31) must be integrated and runtime-commissioned before claiming this replay complete. ## One bounded release

1. Qualify the exact source in private custody. Preserve video identity, original timestamps and native aspect. If transcript, audio or frames are incomplete, narrow public claims and name the limit. Keep source files outside this Git history.
2. Author the canonical three-part brief, recommendation, dated claim register, counterevidence and sanitized receipt in `content/`. Review every existing Reader for substantively supported typed graph routes; record rationale for links or none. Run `python3 scripts/generate_site.py` and `python3 scripts/knowledge_contract.py` once from the final inputs. The latter refreshes the public knowledge Reader inventory, page hashes and claim-register projection from the catalog and generated pages. Exact-passage graph citations still require separate reviewed admission in `knowledge/v0.1/readers.source.json`; a changed cited page fails until an editor reviews and explicitly rebinds its pinned citation provenance. Neither a source link nor an editorial status becomes corroboration automatically. Batch all generated public files into the same local commit. Before any remote write, select the already-authorized delivery route for the execution surface: authenticated Git push where configured, or the authorized GitHub connector where that is the designated primary route. Do not loop over individual Git-tree uploads.
3. Run `python3 scripts/generate_site.py --check`, `python3 scripts/knowledge_contract.py --check`, `python3 scripts/check_site.py`, the full Python tests and `git diff --check`. Check desktop/mobile, opt-in playback, source timestamps, link targets and the public/private boundary. Record selected cues, sections and claims as public-safe paraphrases in `content/source-maps/<slug>.json`. Retain the actual independent editorial/agent findings and limitations in `content/editorial-reviews/<slug>.json`, and make the underlying task report available for Tony to inspect. These candidate-authored files are evidence for his decision, not machine-authenticated proof of an agent’s identity. After opening the candidate PR, set `ownerDecision` to its PR number with `commentId: null` and calculate the single exact line from `scripts/editorial_depth.py`’s `acceptance_marker(receipt)`. Tony evaluates the actual findings and article, then posts that line as his own GitHub PR comment, without the Codex connector. The marker binds the PR number, source identity and private-aid digest, source cue map, retained findings, authored article, evidence and full assessment. Record the comment ID in `ownerDecision` and rerun exact-head CI. The validator fetches the GitHub comment and PR, requires the `pinklon` owner account, no GitHub App mediation, the exact marker, and identical creation/update times. It checks the current CI PR number for an open candidate; after merging, it checks the immutable merge commit for the accepted article, Reader binding, receipt, cue map and findings. Editing or deleting the comment, changing bound bytes, or referencing a different PR fails closed. This is an authenticated owner-account decision and tamper-evident record; code cannot prove who physically typed it, verify private agent identity or determine source truth. If only generated projections or presentation metadata change, retain acceptance while all editorial bindings remain identical.
4. Deliver the exact source to its named public review branch through the previously selected authorized route. Verify the remote ref equals the delivered commit. Open one draft PR. ## Proportionate editorial depth

The reviewer first states why the source calls for a brief or extended treatment. A long source, many material claims or a consequential architecture recommendation requires extended mapping. A short or thin source can support a concise article. There is no universal word or citation quota. In either case the reviewer assesses faithful source coverage, the strongest argument, assertion versus observation versus inference, serious counterargument, assumptions and failure modes, a falsifiable test, and an original GhostMesh synthesis. Performance, economics and threat governance are assessed when relevant; a `not-applicable` decision needs a reason. Source timestamps and claim IDs map the analyzed material. An unresolved blocking gap means `revise` or `hold`, not acceptance.
